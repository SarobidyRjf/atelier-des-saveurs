    Erreurs & résolutions

    • Erreur : dossiers modules/nk_clickcollect et themes/atelier vides dans le conteneur.
      Cause : conteneur relancé au démarrage de Windows avant la distribution WSL (restart: unless-stopped).
      Résolution : docker compose up -d --force-recreate prestashop + healthcheck et restart: "no".
    • Erreur : transporteur du module absent des choix au checkout.
      Cause : un transporteur de module n'est retenu que si need_range = 1 (filtre is_module = 0 OR need_range = 1).
      Résolution : need_range = true ; sans effet sur le prix car is_free renvoie 0 avant tout calcul (source : classes/Carrier.php:570, classes/Cart.php:3787).
    • Erreur : back-office en erreur 500 — appParameters.php introuvable.
      Cause : bin/console lancé en root a reconstruit var/cache/dev en root, illisible pour www-data.
      Résolution : chown -R www-data:www-data var/cache ; désormais docker exec -u www-data … bin/console.
    • Erreur : nom du module affiché « Click &amp; Collect ».
      Cause : $this->l() applique htmlspecialchars (source : classes/Translate.php:209).
      Résolution : nom propre écrit sans l() (il n'a pas à être traduit).
    • Erreur : module absent du back-office après git switch develop.
      Cause : la branche n'avait pas encore le module ; Git a supprimé puis recréé le dossier, Docker restait branché sur l'ancien (unhealthy).
      Résolution : docker compose up -d --force-recreate prestashop ; réflexe docker ps après chaque changement de branche.
    • Erreur : messages admin avec le nom technique du champ (« Ce champ est obligatoire : slot_date »).
      Cause : le cœur range ses erreurs par nom de champ (AdminController.php:3727).
      Résolution : remplacement par le libellé (« Date ») dans _childValidation().
    • Erreur : créneaux d'un même jour mal triés (10:00 avant 09:00).
      Cause : _defaultOrderBy n'accepte qu'une colonne.
      Résolution : surcharge de getOrderByClause() pour ajouter l'heure (AdminController.php:3379).
    • Erreur : sans validation, le client passait au paiement avec « Retrait en boutique » et aucun créneau.
      Cause : le cœur considère l'étape complète si le module ne dit rien.
      Résolution : actionValidateStepComplete met completed = false (passé par référence, CheckoutDeliveryStep.php:204) et ajoute un message.
    • Piège évité : MySQL tourne en UTC (12:29) alors que la boutique est en Europe/Paris (14:29).
      Cause : NOW() en SQL aurait proposé des créneaux déjà passés.
      Résolution : « maintenant » calculé en PHP (date(), config/config.inc.php:150) et passé à la requête.

    Erreurs & résolutions

    • Erreur : une date passée saisie 2026-9-30 était acceptée.
      Cause : Validate::isDate accepte un mois sans zéro (classes/Validate.php:757) et la comparaison de chaînes donne "2026-9-30" > "2026-10-19".
      Résolution : date('Y-m-d', strtotime($date)) avant de comparer.
    • Erreur : suppression d'un créneau refusée à tort, colonne « Réservations » trop haute.
      Cause : la réservation est créée dès l'étape livraison ; si le client change de transporteur ou abandonne, la ligne reste sans commande.
      Résolution : ne compter que id_order IS NOT NULL ; le nettoyage des lignes orphelines viendra avec actionValidateOrder (étape 4).
    • Erreur : reinstall.sh ne voyait pas un échec d'installation.
      Cause : prestashop:module renvoie toujours 0 (ModuleCommand.php:154).
      Résolution : analyse du message (« a réussi » / « succeeded »), affichage de l'erreur sinon.
    • Erreur : connexion au back-office impossible après restauration de data/dump.sql avec les identifiants du .env.
      Cause : le dump remplace toute la base, y compris le compte administrateur.
      Résolution : commande du README qui réinitialise l'employé 1 avec ADMIN_MAIL / ADMIN_PASSWD (Hashing::hash, src/Core/Crypto/Hashing.php:90).
    • Erreur : redirection vers le port 8080 quand la boutique tourne sur un autre port.
      Cause : le dump enregistre l'adresse localhost:8080 (ps_shop_url).
      Résolution : README : garder PS_PORT=8080.
    • Constat : le module n'est pas dans le dump (daté du 14/10) : il faut l'installer après la restauration (prestashop:module install nk_clickcollect). Le dump contient 3 produits et 1 catégorie, et non 12 produits / 3 catégories comme noté plus haut : à corriger.
    • Erreur : page blanche à l'activation du thème — Failed to create "/var/www/html/themes/atelier/assets/cache/": mkdir(): Permission denied.
      Cause : le cœur construit un CccReducer à chaque requête et crée ce dossier s'il manque (classes/assets/CccReducer.php:52, appelé depuis classes/controller/FrontController.php:226) ; or themes/atelier/ est monté depuis WSL et appartient à mon compte, pas à www-data. Le dossier existe bien dans themes/classic, mais Classic vit dans le volume Docker.
      Résolution : créer assets/cache/ dans le dépôt avec un .gitignore qui n'y garde que lui-même, puis docker exec prestashop chown -R www-data:www-data themes/atelier/assets/cache ; procédure ajoutée au README.
    • Erreur : plusieurs règles du thème restaient sans effet (gélule du panier grise, menu en majuscules).
      Cause : Classic écrit ces règles avec un identifiant (#header .header-nav .blockcart, #header .header-top a[data-depth="0"]) : un sélecteur à base de classes est moins spécifique, donc ignoré, même en étant chargé après.
      Résolution : reprendre le #header dans nos sélecteurs. Deux exceptions au !important : les classes utilitaires Bootstrap text-uppercase, déclarées elles-mêmes en !important, ne peuvent être annulées autrement.
    • Erreur : le panier devenait turquoise dès qu'il contenait un article.
      Cause : règle séparée de Classic sur l'état rempli, #header .header-nav .cart-preview.active{background:#24b9d7}.
      Résolution : couvrir les deux états (vide et rempli) dans la même règle.
    • Erreur : titres écrits « Confiture De Fraises » et sections en capitales accentuées.
      Cause : Classic applique text-transform: capitalize aux titres de produit et text-transform: uppercase à .h1, .h2, .h3.
      Résolution : une seule règle globale qui rétablit la casse normale, plutôt que des corrections page par page. Les majuscules accentuées se lisent mal en français.
    • Erreur : le logo chevauchait les icônes sur mobile.
      Cause : Classic dispose la rangée mobile de l'en-tête en float (.float-xs-left / .float-xs-right) ; le logo, qui suit, passe dessous.
      Résolution : rangée passée en flex avec order, sans toucher au balisage de Classic.
    • Erreur : le lien « Toutes les meilleures ventes » renvoyait une 404 vers /meilleures ventes.
      Cause : l'URL simplifiée de cette page contenait une espace dans ps_meta_lang — une donnée de l'installation française, pas un défaut du thème.
      Résolution : normalisation par Tools::str2url() ; corrigeable aussi au back-office (Préférences > SEO et URL).
    • Erreur : OrderHistory en ligne de commande : ComputingPrecision::getPrecision(): Argument #1 must be of type int, null given.
      Cause : en CLI le contexte n'a ni boutique ni devise, et le recalcul de la facture en a besoin (classes/Context.php:557).
      Résolution : initialiser Context (shop, language, currency, country, employee) avant d'appeler l'API. Au passage, la première commande avait été comptabilisée avant l'erreur mais sans sa ligne d'historique : complétée ensuite, sans double comptage (changeIdOrderState ne recompte pas si l'état courant est déjà payé).
    • Erreur : en-tête replié sur trois lignes dès qu'un client était connecté.
      Cause : le conteneur était un flex avec flex-wrap ; le nom du client s'ajoute aux liens du compte, la somme des largeurs dépassait, et le bloc « compte + panier » basculait sur sa propre ligne.
      Résolution : conteneur passé en grille CSS avec des zones nommées (grid-template-areas) : le placement ne dépend plus de la largeur des contenus.
    • Erreur : le panneau de la lettre d'information restait étroit et son bouton chevauchait le texte.
      Cause : trois contraintes de Classic — max-width: 50rem sur .block_newsletter, un bouton d'envoi en position: absolute (hérité de la barre de recherche, qu'il partage), et la classe col-12 qui n'existe pas : Classic est en Bootstrap 4 alpha, où la classe sans point de rupture s'écrit col-xs-12.
      Résolution : les trois remises à zéro dans custom.css, au niveau de spécificité imposé par Classic, et col-xs-12 dans le gabarit.
    • Erreur : le bouton « Ajouter au panier » dépassait du cadre de la carte.
      Cause : white-space: nowrap empêche un élément flex de descendre sous la largeur de son texte, et une carte de la grille d'accueil ne laisse qu'environ 218 px utiles.
      Résolution : min-width: 0 (qui lève la largeur minimale implicite d'un élément flex), retour à la ligne autorisé, et libellé visible raccourci en « Ajouter » avec l'intitulé complet en aria-label pour les lecteurs d'écran.
    • Astuce : le gabarit de ps_contactinfo écrit « Appelez-nous : » en texte brut, hors de toute balise — impossible à styler séparément du numéro, a priori.
      Résolution : dans un conteneur flex, un nœud de texte devient un élément à part entière : passer #contact-link en colonne suffit à empiler le libellé et le numéro, sans surcharger le gabarit du module.
    • Piège évité : j'avais conclu du code du cœur qu'aucun bouton « favoris » n'apparaissait sur les cartes produit (le hook displayProductActions n'est appelé que dans catalog/_partials/product-add-to-cart.tpl:64, donc sur la fiche). La capture d'écran montrait pourtant des cœurs : blockwishlist les injecte en JavaScript (public/product.bundle.js).
      Leçon : lire le code du cœur ne suffit pas quand un module agit côté navigateur — il faut regarder la page rendue.
    • Piège évité : sur les captures faites depuis un fichier HTML enregistré (file://), les icônes Material s'affichent en toutes lettres (« shopping_cart », « mode_edit ») et semblent se chevaucher : la police d'icônes n'est pas chargée. Ce n'est pas un défaut du thème, les pages servies en HTTP sont correctes.
    • Piège évité : trois « défauts » signalés par une première relecture faite sans le conteneur étaient faux (refuseStep par référence fonctionne, guillemets doubles en SQL sans risque, tri sur la colonne calculée sans erreur).
      Leçon : vérifier dans le code réel du cœur avant de corriger.
